# 🛠️ Troubleshooting Approach Developed

During the first 50 days, a major focus was learning to troubleshoot systematically rather than changing configurations randomly.

## Troubleshooting Flow

```text
Problem
   ↓
Collect Evidence
   ↓
Check Configuration
   ↓
Isolate the Layer
   ↓
Identify Root Cause
   ↓
Apply Fix
   ↓
Verify
   ↓
Document
```

Examples practiced:

* Incorrect IP configuration
* Wrong default gateway
* VLAN assignment problems
* Trunk problems
* Router subinterface problems
* ACL blocking expected traffic
* NAT/PAT verification
* Linux process/service issues
* Server connectivity
* Cloud infrastructure troubleshooting

# 🧠 Key Lessons From Days 01–50

### Networking

I learned that networking problems should be isolated layer-by-layer and verified using commands and connectivity tests.

### Linux

Linux is not only a command-line operating system; it is an important foundation for servers, troubleshooting, automation and cloud infrastructure.

### Python

Python can be used as a practical IT tool for connectivity checks, file processing and automation.

### AWS

Traditional networking concepts such as networks, subnets, routing and security controls can be mapped to cloud infrastructure.

### Security

Connectivity does not always mean that traffic should be allowed. ACLs and security controls define intended communication.

### Troubleshooting

A working IT professional needs to find the **root cause**, not simply make the problem disappear temporarily.
